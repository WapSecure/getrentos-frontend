# Marketing pages: Core Web Vitals review (M6)

Date: 2026-11-12. Scope: `/`, `/sell`, `/agents`, `/about`, `/home-management`, `/pricing`, `/diaspora`, `/rent`, `/buy`, `/shortlets`, `/land`, listing detail pages (`/rent/[id]`, `/buy/[id]`, `/land/[id]`, `/shortlets/[id]`), the shared `Navigation`, `Footer`, `components/marketing/*`, `app/layout.tsx` and `next.config.ts`.

Targets (p75, mobile): LCP ≤ 2.5 s, INP ≤ 200 ms, CLS ≤ 0.1.

Method: static review of the code and its import graph (no build, Lighthouse or browser run, per the machine's memory limits). Sizes quoted are gzip sizes of the package's own minified bundle, as an upper bound; the real cost has to be confirmed from a production build (see "Needs measurement").

## What was already in good shape

- **Hero images.** Every page hero (`HomeHero`, `LandingHero`) is a `next/image` static import with `priority`, `sizes`, a blur placeholder and a fixed aspect-ratio frame. No hero is lazy-loaded or rendered on the client only.
- **Hero motion.** `.hero-rise` animates `transform` only, so the hero text is visible from the first frame and does not hold back LCP.
- **Detail pages.** The showroom gallery's first photo is `loading="eager"` + `fetchpriority="high"`, server-rendered visible (`ProgressiveImg` only hides a photo still loading after hydration). Market grids mark only the first three cards eager.
- **Heavy libraries.** Leaflet, `leaflet-draw` and the land price chart (recharts) are already `import()`/`next/dynamic` loaded. No public page imports recharts, date pickers or the Smile ID SDK.
- **Marketing sections are server components.** Only `HeroSearch`, `Navigation`, `ThemeSwitch` and `FaqList`'s disclosure ship JS.
- **CLS.** No cookie/consent or "join" banners exist. The nav is `position: fixed` with a fixed height. `next/font` adds size-adjusted fallbacks (default `adjustFontFallback`), so the `display: swap` font swap moves very little.
- **INP.** The nav scroll listener is `passive` and only flips a boolean (React skips identical state). The hero search's suggestions are a memoised filter of a short static list.
- **Data caching.** Server fetches use `next: { revalidate: 60 }` (data cache), with the signed-photo window rotation documented in `lib/publicFetch.ts`.

### Options for #1 (static marketing pages)

The nonce-based CSP is what forces dynamic rendering: Next can only put a per-request nonce on its inline scripts by rendering per request. The 2026-09 landing work measured `/` going from dynamic to static as part of mobile LCP 3.2 s → 1.1 s, so this is likely the largest single regression since then. Options, all needing security sign-off:

1. **Keep the nonce on signed-in areas only.** Move the `headers()` read out of the root layout into the role layouts that need it, and give public routes a CSP without a nonce (hash- or `'self'`-based). Public pages could then be statically rendered and CDN cached.
2. **Next's SRI (`experimental.sri`) + hash-based CSP** for public routes, so their scripts are allowed by hash and the HTML can be static.
3. **Accept dynamic rendering** and lean on the data cache plus the timeouts added here, keeping TTFB low through hosting (edge region near Lagos, warm instances).

The CSP is currently **Report-Only** unless `NEXT_PUBLIC_CSP_ENFORCE=true`, so the nonce costs performance today without blocking anything; worth weighing in that decision.

## What changed in this PR

- `app/layout.tsx`: Newsreader `style: ['normal']`.
- `components/shared/security/StepUpDialog.tsx`: subpath import; `@simplewebauthn/browser` via `import()`, preloaded at idle when a session exists.
- `lib/store/authStore.ts`: realtime socket module loaded on logout.
- `lib/publicFetch.ts`: `publicFetchInit({ timeoutMs })` and `OPTIONAL_FETCH_TIMEOUT_MS` (3 s), used only where a section can render without its data.
- `app/page.tsx`: `DiasporaSection` async component (parallel with the listings fetch), 3 s timeout.
- `lib/diasporaAvailability.ts`: optional `timeoutMs` (the `/diaspora` pages still wait, since they 404 when it is off).
- `lib/latestListings.ts`, `app/rent/page.tsx`, `app/buy/page.tsx`: 3 s timeout.
- `components/home/LatestListings.tsx`: photos lazy.
- `app/pricing/page.tsx` (server) + `components/pricing/PricingView.tsx` (client) + `hooks/usePlanPricing.ts` (`initialData`).
- Barrel → subpath imports in the 47 files reachable from the public routes.

Logged-in pages: behaviour is unchanged. The only shared code touched is the step-up wrapper (same dialog, WebAuthn loaded on demand), `authStore.logout` (same order, now async-imports the socket module) and `usePlanPricing` (new optional argument; `BillingPage` passes nothing).

## Needs measurement on a real deployment

1. **Real-user Web Vitals.** Nothing reports them today. Two privacy-safe options with no new paid service:
   - Next's built-in `useReportWebVitals` (from `next/web-vitals`, no new dependency) sending `{ name, value, rating, path template, device class }` through the existing first-party `lib/analytics.ts` beacon (random per-tab id, honours Do Not Track, no account id). This needs a `web_vital` event type in `@sureground/shared/showroom` and the backend `/analytics/events` DTO, so it is a backend + frontend change and is **not** done here.
   - Vercel Speed Insights, only if the site is hosted on Vercel (no deployment config in this repo says so) and its plan covers it.
2. **Bundle effect.** Confirm #2, #3 and #9 from a production build: read `.next/server/app/page_client-reference-manifest.js` (and the `/rent/[id]` one) and compare first-load JS for `/` before and after.
3. **TTFB / LCP for #1 and #5.** Check `x-nextjs-cache` / `Cache-Control` on `/` and the server timing with the API cold, then decide on the CSP option.
4. **Font swap.** Confirm on a throttled phone that the Newsreader swap on the hero `h1` stays well under 0.1 CLS.
5. **Lab check** (CI or a staging Lighthouse run, mobile, 4× CPU, slow 4G) for `/`, `/pricing`, `/rent`, `/shortlets` and one listing detail page.
