### 1.3 Mobile product breadcrumbs (Sentry, not analytics)

`apps/mobile/lib/analytics.ts` has a second `track()` that turns events into Sentry breadcrumbs. Breadcrumbs only leave the device attached to an error report, so they cannot be counted as a funnel. `identify()` sets the Sentry user id after sign-in (`lib/auth/AuthProvider.tsx`). `lib/monitoring.ts` sets `sendDefaultPii: false`.

Fired today: `listing_viewed`, `search_performed`, `filters_applied`, `sort_changed`, `discover_view_mode_changed`, `application_started`, `application_submitted`, `application_withdrawn`, `viewing_requested`, `listing_saved`, `listing_unsaved`, `market_*`, `push_*`, `ota_update_downloaded`.

Declared in the type but never fired: `sign_in`, `message_sent`, `app_error`. **Implemented:** `sign_up_started` and `sign_up_completed` now fire from `lib/auth/SignupContext.tsx`, and `rent_payment_started` from `app/(app)/payments.tsx`; each also sends the first-party event in section 1.5, so the sign-up and payment steps can be counted.

### 1.4 What does not exist

- No third-party analytics on web, back office or mobile: no Google Analytics or Tag Manager, PostHog, Plausible, Segment, Vercel Analytics or similar.
- ~~No Core Web Vitals reporting.~~ **Implemented** (section 1.5): `web_vital` for a sample of sessions.
- No error tracking on web or back office (Sentry is mobile and backend only).
- ~~No campaign attribution.~~ **Implemented** as coarse first-touch fields on `session_start` (section 1.5).
- ~~No search or sign-up events on web.~~ **Implemented** (section 1.5). Still none for sign-in, or for rent, deposit or booking payments on web.
- No event carries an account id. Sign-ups and paid actions are counted per anonymous session, not per person (see section 4).
- The back office Listing funnel page does not show the new events yet; query the `ShowroomEvent` table directly until it does.

The Cookie Policy (`apps/web/app/cookies/page.tsx`) says: "We do not currently use advertising cookies or analytics cookies. If we add them, we will update this page and ask for your consent first."

The `*_submitted`, `pro_checkout_start` and `signup_*` events fire only when the API call succeeded (`trackOnSuccess` in `apps/web/lib/analytics.ts`). They deliberately carry no listing id: a listing id and a timestamp could be matched to the account that made the application or offer.

Notes:

- `path` is built by `lib/routeTemplate.ts` from the route's dynamic params, so `/rent/abc123` is sent as `/rent/[id]`. Unknown or id-like segments become `[id]`.
- UTM values are lowercased, limited to `a-z 0-9 . _ -` and 60 characters, and dropped if they hold a run of seven or more digits. Only `utm_source`, `utm_medium` and `utm_campaign` are read. The referrer is reduced to its host, and our own host is ignored.
- The search event fires when the set of filters in use changes, so refining the typed text does not send another event. The view a page opens with is not counted.

### Joining anonymous sessions to sign-ups and payments

Today's design deliberately cannot say "this session signed up". Two honest options, both **Proposed** and both needing a product and privacy decision:

1. **Server-side counts only.** Count sign-ups, Pro subscriptions and payments from the API's own tables by day and role. Compare them with session counts for the same day. This gives rates, not per-user journeys, and needs no consent change.
2. **Consented attribution.** After consent, send the anonymous `sessionId` once with the sign-up request, so the API stores the first-touch landing page and UTM values against the new account. This links behaviour to a person, so it needs consent and an updated Privacy Policy first.

We recommend option 1 for launch.

## 4. Privacy and NDPA

Nigeria Data Protection Act 2023 points that apply here. This is not legal advice, and counsel should review before launch.

| Rule                                                                                                       | Status                                                                                                                                                                                                                                                                                                                                                                              |
| ---------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| No PII in event properties: no names, emails, phone numbers, addresses, free-text search terms or user ids | The showroom and funnel schemas have no free-text fields; the backend rejects any event with an unknown prop key or a value outside its list or pattern. **Gap:** the mobile breadcrumb `search_performed` sends `{ q }`, the raw search text, which can contain a name or address. It only reaches Sentry with an error report, but it should be dropped or reduced to `hasQuery`. |
| Anonymous by design                                                                                        | Holds: random per-tab or per-launch session id, credentials omitted, and the API never reads the caller.                                                                                                                                                                                                                                                                            |
| Retention limit                                                                                            | 400 days, enforced daily by the API.                                                                                                                                                                                                                                                                                                                                                |
| Do Not Track                                                                                               | Honoured on web. Mobile has no equivalent setting.                                                                                                                                                                                                                                                                                                                                  |
| Consent                                                                                                    | No banner exists. The current events set no cookie (the web session id is in `sessionStorage`), which is why the Cookie Policy can say there are no analytics cookies. **Implemented (pending legal review):** the Privacy Policy (`app/privacy/page.tsx`) now has a "How we measure use of the site and app" section.                                                              |
| Adding any third-party tool                                                                                | Needs consent before it loads, an update to the Cookie and Privacy Policies, and a check of where the data is stored outside Nigeria. Also update `proxy.ts` CSP origins.                                                                                                                                                                                                           |
| URLs                                                                                                       | `session_start` and `web_vital` send the route pattern (`/rent/[id]`) from `lib/routeTemplate.ts`, never the query string. Any future `page_view` must do the same.                                                                                                                                                                                                                 |
| UTM values                                                                                                 | Implemented with three keys (source, medium, campaign), lowercased, capped at 60 characters, phone-like values dropped.                                                                                                                                                                                                                                                             |
