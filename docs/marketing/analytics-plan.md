Every statement about the system below comes from code in this repository or the backend repository. Anything marked **Proposed** does not exist yet. There are no baseline numbers in this document: none have been exported, and we should not quote any until they have been.

## 1. What exists today

### 1.1 Anonymous showroom events (web and mobile, stored by the API)

| Part                  | Where                                                                                                                                                                                  | What it does                                                                                                                                                                                                                                |
| --------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Event names and shape | `packages/shared/src/showroom/events.ts`                                                                                                                                               | 16 allowed names (`SHOWROOM_EVENT_NAMES`), the props allowed on them, and `CARD_IMPRESSION_RULE`. The list must match the backend allow-list.                                                                                               |
| Web transport         | `apps/web/lib/analytics.ts`                                                                                                                                                            | `track()` queues events and posts them in batches of up to 50 to `POST {API}/analytics/events` every 5 seconds, and with `sendBeacon` when the tab is hidden. | Mobile transport      | `apps/mobile/lib/showroomAnalytics.ts`                                                                                                                                                 | `trackShowroom()` sends the same events to the same endpoint, with no token, user id or device id.                                                                                                                                          |
| Session id            | both transports                                                                                                                                                                        | A random UUID per browser tab (web, in `sessionStorage`) or per app launch (mobile). It is never linked to an account.                                                                                                                      |
| Added to every event  | both transports                                                                                                                                                                        | `occurredAt`, `sessionId`, `device` (phone, tablet or desktop, from screen width) and, on web, `connection` (`navigator.connection.effectiveType`) when the browser reports it.                                                             |
| Ingest                | backend `src/modules/analytics/showroom-events.controller.ts`                                                                                                                          | Public route, throttled to 120 requests a minute. It never reads the caller, so events stay unlinked even when a token is sent. Invalid events are dropped.                                                                                 |
| Retention             | backend `src/modules/analytics/showroom-retention.service.ts`                                                                                                                          | Rows older than 400 days (`SHOWROOM_EVENT_RETAIN_DAYS`) are deleted daily at 05:00.                                                                                                                                                         |
| Reporting             | backend `GET /admin/analytics/showroom-funnel` (staff roles only); back office page `apps/backoffice/app/(dashboard)/admin/showroom-funnel/page.tsx` ("Listing funnel" in the sidebar) | Per market, sessions computed in SQL: impression → detail view, then detail view → enquiry, inspection, booking, offer, gallery, video and tour. **Impression rule.** Since #182 a card counts as seen when at least half of it is on screen for one continuous second, once per page or screen visit, on both web and mobile. Impression counts before and after that merge (2026-11-12) are not comparable.

### 1.3 Mobile product breadcrumbs (Sentry, not analytics)

`apps/mobile/lib/analytics.ts` has a second `track()` that turns events into Sentry breadcrumbs. Breadcrumbs only leave the device attached to an error report, so they cannot be counted as a funnel. `identify()` sets the Sentry user id after sign-in (`lib/auth/AuthProvider.tsx`). `lib/monitoring.ts` sets `sendDefaultPii: false`.

Fired today: `listing_viewed`, `search_performed`, `filters_applied`, `sort_changed`, `discover_view_mode_changed`, `application_started`, `application_submitted`, `application_withdrawn`, `viewing_requested`, `listing_saved`, `listing_unsaved`, `market_*`, `push_*`, `ota_update_downloaded`.

Declared in the type but never fired: `sign_in`, `sign_up_started`, `sign_up_completed`, `message_sent`, `rent_payment_started`, `app_error`.

### 1.4 What does not exist

- No third-party analytics on web, back office or mobile: no Google Analytics or Tag Manager, PostHog, Plausible, Segment, Vercel Analytics or similar.
- No Core Web Vitals reporting (`useReportWebVitals` and `web-vitals` are not used).
- No error tracking on web or back office (Sentry is mobile and backend only).
- No campaign attribution: UTM parameters and referrers are not captured.
- No search, sign-up, sign-in or payment events on web.
- No event links a session to a sign-up or a paid action, by design (see section 4).

The Cookie Policy (`apps/web/app/cookies/page.tsx`) says: "We do not currently use advertising cookies or analytics cookies. If we add them, we will update this page and ask for your consent first."

### Joining anonymous sessions to sign-ups and payments

Today's design deliberately cannot say "this session signed up". Two honest options, both **Proposed** and both needing a product and privacy decision:

1. **Server-side counts only.** Count sign-ups, Pro subscriptions and payments from the API's own tables by day and role. Compare them with session counts for the same day. This gives rates, not per-user journeys, and needs no consent change.
2. **Consented attribution.** After consent, send the anonymous `sessionId` once with the sign-up request, so the API stores the first-touch landing page and UTM values against the new account. This links behaviour to a person, so it needs consent and an updated Privacy Policy first.

We recommend option 1 for launch.

## 4. Privacy and NDPA

Nigeria Data Protection Act 2023 points that apply here. This is not legal advice, and counsel should review before launch.

| Rule                                                                                                       | Status                                                                                                                                                                                                                                                                                                |
| ---------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| No PII in event properties: no names, emails, phone numbers, addresses, free-text search terms or user ids | The showroom schema has no free-text fields. **Gap:** the mobile breadcrumb `search_performed` sends `{ q }`, the raw search text, which can contain a name or address. It only reaches Sentry with an error report, but it should be dropped or reduced to `hasQuery`.                               |
| Anonymous by design                                                                                        | Holds: random per-tab or per-launch session id, credentials omitted, and the API never reads the caller.                                                                                                                                                                                              |
| Retention limit                                                                                            | 400 days, enforced daily by the API.                                                                                                                                                                                                                                                                  |
| Do Not Track                                                                                               | Honoured on web. Mobile has no equivalent setting.                                                                                                                                                                                                                                                    |
| Consent                                                                                                    | No banner exists. The current events set no cookie (the web session id is in `sessionStorage`), which is why the Cookie Policy can say there are no analytics cookies. **Gap:** the Privacy Policy (`app/privacy/page.tsx`) does not describe the anonymous usage measurement. Add a short paragraph. |
| Adding any third-party tool                                                                                | Needs consent before it loads, an update to the Cookie and Privacy Policies, and a check of where the data is stored outside Nigeria. Also update `proxy.ts` CSP origins.                                                                                                                             |
| URLs                                                                                                       | `page_view` must send the route pattern (`/rent/[id]`) or path without the query string, because query strings can hold names or phone numbers typed into search.                                                                                                                                     |
| UTM values                                                                                                 | Keep only the five standard keys, and cap their length.                                                                                                                                                                                                                                               |

## 6. Rollout order (Proposed)

1. Privacy Policy paragraph on anonymous measurement; drop `q` from the mobile `search_performed` breadcrumb.
2. `page_view` with UTM capture, and `search_submit`, both in the shared schema and the backend allow-list.
3. `*_submitted` events next to the existing `*_start` events.
4. `signup_*`, `pro_checkout_*` and `payment_*` events, plus the server-side daily counts (option 1 above).
5. `web_vital`.
6. Extend the back office Listing funnel page with the new stages.
